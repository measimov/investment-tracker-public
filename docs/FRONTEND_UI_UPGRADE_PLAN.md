## 3. Claude 研究：观察与采用边界

Claude 官方 frontend-design 技能强调用途、内容和可辨认的设计方向，要求检查字体、配色、布局和实际效果。
它同时警惕“米白背景、衬线标题、陶土色”本身变成通用模板，因此不能把换成暖色当作全部升级。
官方页面观察到 `#FAF9F5` 背景、`#141413` 深色文字、`#C6613F` 强调色，以及 `anthropicSans` / `anthropicSerif` 字体家族名称。
这些是对所查看官网页面的观察，不代表 Claude 所有产品界面的完整设计规范，也不是字体可免费分发的许可。
不下载或打包专有品牌字体；不把营销页的大留白、居中标题和巨型字号照搬进金融表格。
Claude 产品帮助文档另确认可折叠侧栏、明暗外观与聊天字体偏好；这些说明产品提供选择，不构成本项目新增设置功能的理由。
Claude Design 的官方介绍强调从现有代码、组件和设计规范出发，再预览与调整；本项目按此方式复用现有基础。

可采用的具体原则：

- 布局：内容优先，主任务明显，分区靠间距和表面差异；只有真实分组需要时才增加卡片。
- 字体：少量字号与字重建立层级；操作界面易扫读，研究长文易连续阅读。
- 色调：中性底色、可靠文字对比、一种主要交互强调色，业务状态单独表达。
- 交互：按钮文案说明动作；操作反馈就地可见；次要信息按需要展开。
- 动效：服务于状态变化与展开关闭，不加装饰性入场、漂浮或缩放效果。
- 验收：通过当前内容、长文本、未知值、失败状态、键盘和窄屏检查设计是否成立。

开源实践的具体取舍：Carbon 的表格空间与工具栏分组适合持仓/交易；Ant Design 的系统字体、数值对齐适合高密度金融数据；现有 Element Plus 的滚动、展开与对话框机制作为功能对照；ECharts 保留现有图表实现并补足文字解释。视觉原则与最终组件选型分开决定。

### D2 已确认实施方案

实际导航共有 10 个普通用户入口、13 个管理员入口；现有顶栏将三个普通入口放进“更多”，在 ≤1100px 时变成两行。
这些都是目前已有页面，因此左侧纵向分组能减少入口藏在下拉菜单的情况，具有实际使用价值。
研究基线持仓表列宽约为合并视图 1036px、账户视图 1072px；已交付试点的 scroll-x 为 1196/1232px。展开左栏确实减少可用宽度，完全收起后恢复全宽；实施时按真实试点验证，不沿用旧列宽估算。
原先以“左栏影响表格”为由推荐顶栏过于笼统。用户已确认以下最小方案：

- 桌面侧栏展开约 224px，容纳图标和完整中文名称；常用、其他、管理员分组，复用现有菜单定义与权限过滤。
- 点击收起后完全隐藏，占宽 0px；页头始终保留有名称的展开按钮。不再增加一个 64px 图标条模式。
- 页面内容立即使用释放的宽度；内容最大宽度约束施加在内容区，不将侧栏和内容一并挤进原 1440px 外壳。
- ≤1100px 使用左侧覆盖抽屉，关闭后不占空间；点击导航、遮罩或关闭按钮后关闭，键盘焦点正常返回。保留现有机制作为验收基线，具体组件随 D4 落定。
- 桌面只记住一个本地展开/收起偏好，切页保持，不新增数据库设置，也不按页面自动变更。
- 无偏好时桌面首次展开；若 1280px 表格需要更大空间，用户可一次收起并记住。窄屏抽屉始终默认关闭，窄屏打开不覆盖桌面偏好。
- 不做拖拽宽度、悬停自动弹出、多级自定义导航、每页独立记忆；保留已有 activeMenu、详情页 meta.nav、管理员权限和账号操作。
- 验证侧栏开关后表格/图表尺寸与滚动正确、焦点不会留在隐藏菜单、缩放及窄屏切换不遮住关键操作。

展开侧栏时宽表可能需要局部横向滚动，完全收起后恢复内容宽度。按最新试点列宽验证 1440/1280/1024px 与开关后的图表尺寸，不通过缩小金额或隐藏列换取表面上不滚动。

雪球能力隐藏：

- 无配置且无可读历史时才隐藏普通用户入口；Cookie 失效或采集暂时失败不能让已有内容消失，管理员保留配置入口。
- 能力查询只读本地配置与既有可读历史是否存在，复用当前来源判定；不能只检查可选行情包，漏掉内置采集器、历史摘要或标的帖子。

- 覆盖普通用户/管理员、无配置无历史、失效有历史、仅摘要/仅帖子、查询失败及会话切换。历史访问遵循既有权限，不改账本、来源关系或历史产物；响应变化同步生成 API 类型。

## 5. 布局规范

页面顺序以“标题与主要动作 → 当前范围和筛选 → 关键结果 → 明细及依据”为起点。
每页有一个明确 `h1`，文案与导航、标签页标题一致；不把页面标题藏在视觉上无差别的卡片标题里。
主内容沿用最大约 1440px 的现有外壳；不为统一外观强制窄化宽表格。
常规页边距建议桌面 24px、窄屏 16px、手机 12–16px，复用现有间距变量。
分区间距建议 24px，组内 12–16px，紧密标签与数值间 4–8px；实施时尽量映射现有 token。
表单筛选与它影响的数据相邻；常用范围保持可见，手机沿用已有折叠筛选和生效数量提示。
页头只突出一个主要任务；刷新、导出和耗时批量操作分组，低频操作可用已有菜单。
不把所有 KPI 做成独立大卡片；同一口径内相关指标可以共用一个表面与细分隔。
不依赖固定高度制造整齐；长名称、异常说明、七位数金额必须有实际容纳空间。
全局导航依 D2 落定；手机沿用可关闭抽屉，不引入底部导航与第二套菜单维护。

## 6. 字体与数字

| 用途 | 建议字号/行高 | 处理 |
|---|---|---|
| 页面主标题 | 24px / 1.3，600–700 | 一页一个；手机按实际空间调整 |
| 分区标题 | 16–18px / 1.4，600 | 与普通标签明确区分 |
| 常规正文与表单 | 14–15px / 1.5–1.6，400 | 保持中文扫读效率 |
| 表格数据 | 13–14px / 1.5，400–500 | 金额右对齐，不任意缩字塞入 |
| 说明与元信息 | 12–13px / 1.5 | 关键口径优先用 13px 与足够对比 |
| 核心金额 | 24–28px / 1.2–1.3，600 | 按实际位数校验，不全站巨型数字 |
| 研究文章正文 | 16px / 1.75，400 | 限制文本行宽，长表保留独立滚动 |

继续使用现有系统字体栈，中文优先系统可用的苹方、微软雅黑等；不新增网络字体依赖。
暖色方案可仅在页面主标题尝试系统宋体/衬线字体；表格、按钮、数字和研究正文仍用无衬线字体。若中文显示不稳定，标题也回到系统无衬线，不为外观新增字体下载。
手机输入框文字沿用至少 16px；14–15px 是桌面正文与表单标签建议，不覆盖现有防止聚焦自动缩放的移动规则。
研究正文建议约 60–75 个拉丁字符或 30–40 个汉字的行宽；数据表、图表和结构化指标不受文章窄栏限制。
金额、数量、日期和比例使用 `font-variant-numeric: tabular-nums`；不把全部中文界面换成等宽字体。
金额、价格、数量、百分比、日期继续由 `helpers.ts` 输出；不得因为视觉统一丢失价格精度。
负号在币种符号之前；需要正号时用明确一致的 formatter，符号与数字作为完整字符串显示。
真实零显示零，未知显示 `—`；缺值不拼接 `%`，不通过 `|| 0` 变成零。
原币与 CNY 不能仅靠颜色区分；主/副行标清币种与折算口径，避免裸数字混淆。
表格内已有独立币种列时可保留这种清晰结构，不为“统一”机械给每个单元格重复货币符号。
日期走既有 formatter；带时区时间保留 `formatDateTime`，禁止切片取日期。

## 7. 色调与表面

用户已选择 A 列作为项目配色方向；B 列仅保留为原方案对照，不实现主题切换。这不是 Claude 官方完整标准：

| 角色 | A：暖中性建议 | B：保留现有体系 |
|---|---|---|
| 页面背景 | `#FAF9F5` | `#F5F6F8` |
| 主内容表面 | `#FFFFFF` | `#FFFFFF` |
| 主文字 | `#242321` | `#0F172A` |
| 主要交互色 | 深陶土 `#A6533C` | 靛蓝 `#4F46E5` |
| 次要文字 | `#5F5B53` | 沿用 `#475569` / `#64748B` 并验证 |
| 分隔与选中背景 | `#E5E1D8` / `#F2E8E1` | 收敛现有 slate / indigo token |

官网观察的 `#C6613F` 不直接用于所有小字号按钮文字；候选 `#A6533C` 用于提高白底/暖底上的对比度。
所有候选值须在最终前景与背景组合上实际检查，不能只因颜色“看起来深”就认定达标。
候选的基础组合已计算：`#A6533C` 对白色约 5.35:1，`#5F5B53` 对 `#FAF9F5` 约 6.41:1，`#242321` 对 `#FAF9F5` 约 14.90:1；这不替代实施后对 hover、disabled、标签等实际组合的检查。
普通文字对比至少 4.5:1，大字至少 3:1；焦点、边界与状态也保持可辨识。
保留用户已有的盈利绿、亏损红语义；同时显示正负号或文字，禁止只靠红绿传递结果。
小字号盈亏文字若当前颜色对比不足，使用同色系更深值，例如白底 `#047857` / `#B4233E`，不改变正负含义。业务盈亏与普通成功/失败提示在用法上区分，不需要建设新主题系统。
估算/待核对使用中性或适量琥珀提示；不能拿成功色表示“已到账”，除非确有该状态事实。
交互强调色不承担财务涨跌含义；刷新按钮不借用盈利绿表达普通动作。
状态强调只作用于必要数字、标签与说明，不给大面积整卡染红、染绿或堆叠多个醒目横幅。
项目颜色统一同步 `styles/tokens.ts` 的画布值；保留 Element Plus 时统一 `--el-text-color-*`、警告色与 `--app-*` 映射，替换时将同一视觉语义映射到所选库的主题机制。
卡片保留细边框和小圆角；阴影仅用于浮层，沿用 150ms 左右颜色变化与减少动态效果支持。
正式实现优先保留现有 6px 卡片、4px 控件圆角；图标使用已有 Element Plus 图标，常用 16–20px，不引入第二套图标。

## 8. 表格与明细

以现有表格的必要业务行为为基线，组件由 D4 决定；优先给数据充分宽度，避免嵌在狭窄描述列表或多层小卡片中。
短文本/数值行以约 40–44px 为起点；含两行账户、币种或行情日期的行按内容适配。
名称列可合理两行或截断并提供可操作的详情入口；金额、日期、状态不能拆成难读竖列。
长趋势、业务解释、来源和审计依据使用已有展开区或整行段落，不塞进固定窄列。
金额列右对齐并保留有效位，数量和价格各用自己的格式化函数。
表头清楚表达单位、币种、账户范围；空间不足时用第二行说明，不能省略关键口径。
按需固定关键识别列和操作列；窄屏固定列不能占满内容区。
核对所选表格组件内部滚动与外层容器，避免重复滚动和 sticky 冲突；保留当前实现时先查 Element Plus 与 `responsive-table` 的关系。
移动表格可以局部横向滚动，显示足够的滚动暗示；重要操作尽量在首屏可发现。
手机卡片只用于已存在模式或确有频繁操作障碍的页面，不为每张表重复建立卡片版。
统一行操作的文本按钮、顺序与尺寸；导入只读记录继续明确标记，不出现可写假象。
统一空表、筛选无结果、加载失败的表达，保留对应清筛选或重试动作。
没有后端排序支持的分页表不增加“只排当前页”的误导性排序按钮。

## 9. 图表

继续使用 ECharts，沿用现有计算与数据请求；分类色在仪表盘和统计页保持一致。
分类色不借用盈利/亏损语义给市场贴好坏含义，灰色不代表未知时不得混用。
曲线区域同时标明区间、单位、币种、收益口径和数据不足说明。
本轮不新增待收收益曲线；已有曲线和 XIRR 的实收语义不因卡片升级发生变化。
如现有图内有估算序列，需文字、线型与颜色共同区分，不用近似浅色单独编码。
图表 tooltip 金额委托既有 formatter；缺值不补零，不制造连接完整的虚假走势。
市场环图可共享已需要的 option 构建函数，保留小范围实现，不创建通用图表描述语言。
补充简短可读摘要；按当前 ECharts 版本验证 aria API，避免照抄新版文档的未支持字段。
手机图例可换行，坐标标签保持可读；无需装饰渐变、3D、动态背景或持续动画。

## 10. 交互、响应式与状态

导航使用 `router-link` 或真正带 href 的链接，支持键盘、中键与新标签；纯开关用按钮。
所有输入有可访问名称；说明图标可聚焦，并能通过点击或键盘打开说明。
关键财务限制、估算状态与失败不能只藏在 hover tooltip 中。
表单明确禁止误点遮罩丢失输入；重开时清理旧校验红字，保留正常焦点返回。
沿用组件对话框焦点管理，验证 Tab/Shift+Tab、Esc 和明确取消按钮；不写全局键盘事件框架。
危险动作使用既有确认函数，按钮写具体动作；操作进行中防重复提交，结果反馈与对象对应。
批量任务继续区别“停止查看进度”和“取消任务”；后台仍运行时不能显示已停止任务。
详情页直接打开时，返回按钮有合理应用内兜底；正常历史导航仍保持可用。
空数据说明尚无记录，筛选空说明范围无结果，失败显示原因及重试，权限不足不伪装空数据。
已知部分、缺汇率、陈旧价格、待核对、仅净额已知使用事实状态；不要一律显示泛化警告。
状态说明建议“一行影响摘要 + 原位展开依据”，影响金额和关键限制默认可见。
移动主要触控目标建议 44px；遵循至少 24×24 CSS px 或间距例外的可访问底线。
响应式复用现有断点与 `useMediaQuery`；先验证 1440/1280/1024/768/393/375px。
320px 等效宽度和 200% 缩放时一般内容可重排；数据表允许自身滚动，整页不得靠隐藏溢出来掩盖控件。
标题、筛选、分页、状态条可换行；七位数金额与负号、币种符号保持完整。

## 12. 财务事实与语义保护

- 普通股息不改变实际买入成本；持仓平均成本与 FIFO 剩余成本的既有区别必须说明。
- 总收益、收益率与 XIRR 保留权益仓口径，不含闲置账户现金与外部入出金；“实收股息口径”仅指股息按实收处理，不等于整个收益都是已实现收益。
- 实收累计与含待收估算保持并列可辨，不用默认开关隐藏其中一方的含义。
- 只有已除息、权益明确的待收进入估算；税未知不能显示零税或免税。
- 累计待收按最新汇率折算，实际到账按净额替换；不把预计股息当作可用现金。
- 月/年含待收口径继续使用现有“实收损益 + 期末待收 - 期初待收”，保留缺口与部分覆盖说明。
- 日损益维持实收股息口径；月/年待收的期初、期末分别使用对应日期汇率，不套用累计待收的最新汇率。
- 收益曲线、XIRR、已有实收区间口径继续按各自既有规则；不借视觉改版重算历史。
- “待核对”不等于没到账；历史未核验、仅净额已知、未知税额不能通过省略提示变成已确认。
- 保留实验指标、估算基准、陈旧价格、缺汇率和风险下限等重要标签。
- 数字展示可以统一，数据库、API 原值、来源关系和会计算法不因本轮计划改变。

## 14. 验证与上线

1. 开发前复用现有演示/E2E 数据建立可重现基线；生产只读截图保持私有。
2. 数据样例覆盖 `0.085`、`1.409`、负金额、真实零、未知、大金额、多币种、长名称、长趋势。
3. 状态覆盖无记录、无筛选结果、加载、失败、部分成功、陈价、缺汇率、待收/实收/待核对、只读导入。
4. 浏览器检查桌面、平板、手机、缩放、键盘、新标签、触控、表单误关、打开关闭焦点。
5. 图表验证区间、图例、tooltip、缺值、颜色一致性与文字摘要，不只看默认有数据页面。
6. 金额格式、状态或交互变化编写针对真实失败条件的回归；纯低风险样式/文案不写镜像实现测试。
7. 按项目要求运行格式、类型、单元、构建与 Playwright；有 API 改动则生成类型并运行对应后端回归/CI。
8. 每个 PR 提供合适视口的前后对照及验收说明；共享截图使用演示数据，不泄露账户、持仓和凭据。
9. 较大界面变化按既有 `demo:capture` 流程更新 `docs/media/`，不以旧截图宣称新版完成。
10. 纯前端改动预期无数据库迁移、财报重算或付费模型调用；D3 后端范围另行说明实际影响。
11. 合入后按用户确认的发布节奏部署，保留旧镜像/前端回退路径，实际验收后才登记闭环。
