# 股息的日期、金额与币种口径

## 预计与实收分离（0042）

普通现金分红不冲减实际买入成本。公告建议仅用于预计与待收统计，现金分红的旧“接受”入口返回 409；送转数量行动仍走既有接受流程。资格尚未确定的预计与权益确定后的待收分开显示，日期过期不等于到账。

实际股息只有 `receipt_status=RECEIVED` 且现金日期不晚于统计截止日时参与实收汇总、现金对账、收益曲线、区间收益和 XIRR。`UNVERIFIED` 保留历史数据及来源，但不参与实际计算。新手工/API/标准 CSV 录入须提供 `payment_date`、账户及 `receipt_confirmed=true`；预计日期不能作为到账证明。

`amount_basis=NET_ONLY` 表示仅实际净到账额已知，税前额、税额留空；净额照常计算，税前/税款摘要显示不完整提示。`GROSS_NET` 表示税前额与税额已核实（明确免税填 0）。历史 `LEGACY` 暂时保留旧计算，不能把 schema 默认值当成新的到账凭据。后续历史升级会逐笔核对公告生成记录。

一份公告可经 `dividend_suggestion_id` 关联多次实际股息。全部到账由人工 `receipt_complete` 确认，或依据真实对账单自动核对完成（规则见下节）。税前额减净额不能当作尚未到账的余额；跨币种或税前金额未知且凭证不能闭合时，不猜剩余预计金额。

0042 仅加字段，不自动改历史金额或状态。代码与 schema 升级、历史数据修复分别验证；旧数据升级前的冻结财务指标应无数值变化。IBKR Flex 自动取数另行实现，当前 connector 汇总余额或应收冲回不能替代现金凭证。


现金股息的统计日期统一为 `payment_date`，缺失时回退到 `ex_date`。公司行动列表、数量与筛选汇总使用这个日期；数量类公司行动仍使用除权日。收益曲线、区间收益、XIRR 与账户现金对账共用 `portfolio.semantics.dividend_cash_date`。原始导入流水的到账日不能自动认作发行人的真实除息日。

收益计算采用现金制。除息到到账之间，证券价格已经除息而股息尚未计入，这段期间的收益可能暂时下降。切换为应收股息口径需要完整的权益与到账关联，不能仅移动日期。

### 累计收益双口径

仪表盘和统计分析页使用同一份 `receivable_return` 展示“当前累计收益（实收股息口径）”“待收股息（税前估算）”和两者相加的累计收益。它是当前时点的补充估算；原有现金、买入成本、实收损益、收益曲线和 XIRR 计算不变。本月、本年另增加并列的含待收损益，见下节。

只有除息日已到、账户与正数权益数量明确的有效公告参与。未除息、已忽略、撤回、被修订替代、明确无权益或全部到账的公告不增加待收收益。同币种 GROSS_NET 部分到账按已收**税前额**扣减剩余预计；仅净额、跨币种、B 股派发币种未核实或权益/金额未知的记录列待核对。存在同账户（含未归属账户）同证券、既有匹配日期窗内的未关联实收时，也不再叠加整笔预计，须先核对关联。

待收估算按最新汇率折成人民币，与现有累计收益金额口径一致。缺汇率的金额保留原币并显示缺口，未知部分不当作零；有缺口时卡片明确标“含已知待收估算”，只合计能确定的部分。待收金额是税前预估，不猜税率，不能把加总结果称为已实现或税后收益。历史 LEGACY 提示继续显示。

例如当前累计收益100元，待收税前股息1000港元，汇率0.9，则含待收估算为1000元。第一笔到账税前400、扣税40、净收360港元后，当前收益变424元、剩余税前预计540元，合计964元；全部到账并确认完成后待收归零，收益按实际净收计算。不会同时累加整笔预计和实际到账。

### 对账单自动核对与提示分类

`dividend_settlement_service` 只读装载到账事实与 `BrokerFundFlow` / `IbkrActivityFlow` 凭证，在同一用户、账户、证券下核对派息期次。只有候选归属唯一、来源金额与账上金额一致、整次派息的金额闭合，才派生 `receipt_complete=true` / `RECEIVED`，并返回 `completion_source=statement`。已有历史凭证与后续导入走相同规则，不需要重新导入或写回历史现金。

同币种 NET_ONLY 的实际净到账与公告税前总额相等或仅有不足一分的尾差时，可以证明整次金额已经收到；这不会把未知税额写成零，也不会将净额字段改为税前额。若实收小于税前总额，不能据此判断是扣税还是部分到账。跨币种只能采用凭证提供的真实原币金额或结算汇率；没有原币到账证据时，不能拿最新汇率、通用税率或“每股金额×历史持股”来冒充券商实付总额。B 股来源币种未核实仍需核对。

一份公告有多次到账时按最后一笔到账日结清，历史截止日在该日前仍保留当时的余额。只靠旧日期窗口匹配、匹配到多个公告、原关联所属期次已失效、来源金额与账本不符均不自动完成。人工明确保存的“未收齐”不会被自动规则覆盖；`completion_source=manual` 表示人工确认。`completion_date` 是末笔到账日，不是执行核对操作的日期。所有推导均不改来源 hash、现金、税额、持仓成本或数据库状态。

累计收益卡片把待核对分为已匹配实收、疑似到账未关联、缺账户/持股、缺金额/币种；已匹配实收再说明仅净额、跨币或 B 股币种问题。剩余已算为零但未结清的记录单列，不叫逾期待收。`pending_overdue_count` 只包含**正数可估算余额**中超过预计派息日的条目；旧 `overdue_count` 为兼容保留，新界面不使用它表示未收数量。超过派息日表示账本尚未确认收齐，不证明券商实际上没付款。

### 本月、本年损益双口径

两页的本月、本年损益保留实收值，并增加 `receivable_pnl`：

> 含待收损益 = 实收损益 + 期末税前待收 − 期初税前待收。

期初为本月/本年首日前一天，期末为业务时区的今天；两端各用对应日或更早的有效汇率。除息前余额为零，到账按实际日期冲销；新口径不改变原收益率、日损益、曲线及 XIRR。比如 6 月除息应收 100 元、7 月净收 90 元：6 月增加预计收益 100 元，7 月增加实收 90 元并冲销待收 100 元，净影响为 -10 元，两月合计 90 元；不会在 7 月再计一次 90 元收益。

`period_receivables` 与累计口径共用公告、来源核对和时点余额。一次请求只装载一遍来源和汇率，月/年重用。任一边的剩余金额无法核实，或该边缺少历史汇率，整笔在**两个边界一起排除**并计入缺口，不能只加期末值却漏扣期初值；缺历史汇率不使用未来汇率回填。显示“含已知待收股息（税前估算）”及缺口数量，不把未知当作确切的零。原实收损益无法计算时，含待收值同样不提供数字。

这是依据当前已保存公告与凭证重建的期间估算，不是当时可知信息的历史版本快照。完整期内收齐时，期初期末均为零，与实收损益相同；跨年尚未到账的历史股息也遵守期初扣除规则。统计页手工价试算通过 POST `/statistics/period-pnl` 与累计摘要使用同一价格集，退出时恢复服务端定价。

上述功能为只读计算和页面展示，无数据库迁移、新 env 或历史数据升级；也不需要重跑财报分析。

公司行动页与统计页的累计股息按最新汇率折算 CNY；收益曲线、期间损益与 XIRR 按各笔流水的日期汇率折算。两者因汇率变化可能不同，缺汇率时均须显示缺口，不能把外币原值当成人民币。

手工录入和标准 CSV 中，显式税额（包括 0）优先；只有税额缺失且提供税率时才推导税额。快捷接口不预设 10% 税率。只有 LEGACY 历史记录沿用旧数值计算；新记录的未知税额必须保留为空，实际税额须依据券商资料核实。送股、拆股等数量变化不能替换已有持仓的交易币种；期初建仓可以建立尚无交易的成本币种，转仓继承原持仓的成本币种。

未指定账户的现金股息仅在除息日前存在唯一持有账户时计入该账户的推导现金；多个账户持有时保持未归属，不重复分摊。现金事件本身仍需指定账户。

## B 股来源限制

[Tushare dividend 接口](https://tushare.pro/document/2?doc_id=103)提供每股金额与日期，但未提供派发币种及发行人换汇率。不能用最新汇率自动转换公告金额，也不能把人民币金额直接标成港元或美元。

例如[古井贡酒 2025 年度权益分派实施公告](https://static.cninfo.com.cn/finalpage/2026-07-10/1225417834.PDF)规定 B 股用指定日人民币兑港元中间价转换派息；B 股最后交易日、除息日与登记日也不同。应按除息前持仓确定权益，并用发行人公告或券商实际入账核实币种、总额和税额。不能因当前税额为 0 就补上统一税率。

## 发布与存量数据

0042 增加预计/实收状态与关联字段，不改写存量股息金额。发布前须备份数据库与环境配置，在隔离恢复库用同一天、同一价格及汇率生成改动前后指标快照；未进行资料修正时应没有数值差异。

涉及重复入账、递延扣税或历史补账的后续改动，应提供单独的迁移及逐行预演清单。原始流水、券商资料、用户实际账本快照与部署凭据只保存在受保护且被 Git 忽略的本地备份目录。

### 0041 及之前的建议与到账合并（历史行为）

招商、东财预览与正式导入共用 `dividend_receipt_service`：同一用户、账户和证券下，真实到账唯一匹配到一个尚未关联券商流水的已接受建议时，原地更新同一条股息，保留公告除息日，补实际到账日、币种、金额和批次，来源流水指向这条记录。

到账只证明净额，跨币种时不能照搬旧估算税额，也不能反推固定税率。原估算总额、税额、币种与新到账来源 hash 保存在建议的 `match_detail.broker_receipt`；同币种显式手工税额保留，跨币种的税前与税额保持待凭证核实，并在行动备注中说明。存量摘要对净额型来源的税前完整性展示仍需后续补齐。

多个公告候选、未明确账户或不同日期/币种的分次到账均阻止自动合并。不同账户不互相匹配，已关联真实来源的股息不再参与估算合并；已入账的相同来源 hash 仍走原有判重通道。原始解析、hash 和归档复活规则不变。

公告除息日更正按发行期间、公告身份和分配类型/比例识别同一分配，撤销未接受的旧日期行；已接受或忽略的历史行保留，并在公告明细中标注取代它的当前除息日。再次同步改回原日期时清除此标记，以源数据的当前版本为准。缺少发行期间或公告身份的来源不推断修订关系。

删除可编辑的股息/送股记录时，仅有效版本的 ACCEPTED 或 MATCHED 建议恢复为 NEW；已被取代的旧接受版本随行动撤销，不能与修订版本同时恢复。用户明确忽略的建议继续保持 IGNORED，被修订取代的旧版本不能恢复或接受。接受入口在日期窗以外仍按分配身份核对实际在账行动及其最终账户，阻止旧客户端或历史 NEW 建议重复入账；不同账户的现金分配保持独立。

接受、修改、删除、同步的账本写入和券商导入共用用户级导入锁，再依次获取记录锁与证券时间线锁，以免实际到账合并与手工编辑并发。

旧版合并行为见以上说明；0042 仅增字段，也不自动合并历史疑似记录。发布后只需重新预览待导入的对账单，核对合并提示再按正常流程导入；历史重复记录须单独列出来源依据后修复。

## 日期独立的股息税（#374）

招商「股息红利税补缴」和东财「股息红利差异扣税」记为 `CashEvent(event_type=TAX, tax_kind=DIVIDEND)`，金额为正，方向为支出，日期为券商实际扣款日。IBKR 同日且唯一匹配的预扣税仍保留在股息中；找不到唯一匹配或扣款日与到账日不同的税，使用独立现金事件。原始来源链接现金事实，重复上传按既有 hash 判重，不再累计回原股息。税额无需股息归属也计入总税费、净股息、现金对账、期间收益、曲线和 XIRR；普通 TAX 现金事件不计入股息收益。

账户数据的「现金事件」中可对股息税选择一笔或多笔股息并显式分摊。候选必须属于同一用户、账户、币种，且股息已到账；各笔分摊为正，合计不超过实际税款，不按最近日期或固定税率猜测。未分摊部分保持可见并已计入总额，证券明细只计明确归属部分。删除股息仅清除该笔归属，真实扣款仍保留。导入的扣款日期、金额等事实继续只读，归属可调整。修改股息、现金事件或合并券商到账不能破坏已有归属。

金额汇总按扣税日筛选，即使原股息在筛选区间外也不漏税。按证券筛选时只汇总明确分摊的税额；不增加股息笔数。历史每日净收入可因扣税而为负。最新汇率汇总与按历史日期 FX 的收益曲线仍遵循前文区别。

股息税在扣款日缺少历史 FX 时，不把外币原值混入人民币现金流。曲线保留扣税日期并标明税款未计入，相关年化/风险指标暂不展示；受影响的期间损益为不可计算。最新汇率金额汇总独立按其自身缺汇率规则提示，不能据此推断历史 FX 已完整。

### 结构迁移与历史升级分开执行

`20261001_0041` 仅新增税款用途及 `dividend_tax_allocations` 表，无新增必填 env，不自动改历史金额。旧账本与 schema 升级后、数据升级前的财务指标应相同。历史数据使用 `scripts/upgrade_dividend_tax_events.py`：默认只读，输出含来源 ID/hash、扣税日期、股息税净额 before/after、显式现金锚点及原券商快照依据的计划。无证券代码或旧 `skip_reason=NULL` 的负股息税也能修复。旧关联税的分摊保留，旧股息税额相应扣除、净额加回，避免重复扣款；无法无损还原的旧净额/币种/账户关联会阻断。

在可丢弃的备份恢复库中，设置该库的 `DATABASE_URL` 后从 `backend/` 运行（占位符按实际核对记录替换，计划文件放在忽略目录）：

```bash
python scripts/upgrade_dividend_tax_events.py --user-id <USER_ID> \
  --anchor <EVENT_ID>:<BROKER_SNAPSHOT_ID> --out ../backups/dividend-tax-plan.json
python scripts/upgrade_dividend_tax_events.py --user-id <USER_ID> \
  --apply-reviewed-plan ../backups/dividend-tax-plan.json --out ../backups/dividend-tax-result.json
```

`--anchor` 可重复；无现金残差锚点时可省略。锚点只抵消已证实税款及旧税日期移动对指定快照日的影响，不能盲加累计税款。若账本已与券商现金不符，默认计划阻断。`--preserve-existing-cash-delta` 仅在明确审阅该差异后用于保持原差额，计划列明原差额及预期余额，不能将其吸收进锚点或称为对账一致。

先验证来源 hash、日期、账户、原币及现金差异，冻结同日价格/FX 双跑 metrics，并逐字段解释变化；再次生成及应用计划应零新增。生产执行前重新备份并验证实际恢复，停 backend/collector 写入，在维护容器执行无阻断且与当前账本完全一致的计划，核对升级结果后再恢复服务。数据升级会改变收益历史，回滚须恢复备份及旧镜像，不能只降 Alembic revision 或删除税款列。

## 0042 三券商到账与人工核对

招商、东财和 IBKR 的预览/提交现在共用到账关联服务，提交时在用户导入锁内重新计算。原始来源及 hash/别名、疑似重复确认流程保留。现金日期以每次实际到账为准；唯一公告可关联多次到账，不同日期不会合成一个现金日。税前预计与净实收不能相减来猜测全部到账。

招商、东财正向红利流水只证明净到账额，记 `NET_ONLY`；即使币种与旧公告相同，也不把旧估算税额当作凭证。IBKR 股息及同日明确关联的预扣税沿用其来源列，异日/无法唯一关联的税继续作为独立现金事件；这不解决旧导出文件基础币种与真实入账币种的证据缺口（#259）。

有多份预计公告可匹配时，真实现金照常记录，公告关联暂留空并提示人工核对；若多份**已计入现金的历史公告**可能被重复记账，则阻止导入，须先执行历史升级。手工确认的相同到账与后续券商凭证复用原记录；手工/标准 CSV 重复提交同账户、日期、币种、金额的现金股息会被阻止。真实存在金额相同的独立款项，应使用带独立来源身份的券商凭证导入。

公司行动的「核对到账」可显式关联同账户、同证券的多笔实际到账，并确认全部到账；金额和税款仍只在凭证记录中。接口使用更新时间防止旧页面覆盖新关联，跨用户/账户/证券和已归属其他公告的记录不能混入。取消关联不删除现金，公告撤回也保留已有现金及审计关系。账户或权益数量错误应修正权益日之前的账本并重新同步，不另建一套可与账本漂移的持仓覆盖值。

编辑已关联到账记录时同样校验账户、证券及行动类型，包括旧版公告匹配关系。与原公告不兼容的修改返回 409，整笔修改回滚；应先在「核对到账」解除关联，再修正记录。解除关联会撤销原公告的全部到账标记，旧匹配字段不会把记录重新关联回来；修改备注不受影响。

补导券商凭证复用已有手工到账时，原公告关联优先于日期窗口产生的新候选。即使原公告已完成、已撤销或超出自动匹配窗口，也要保留原关联及完成状态；原关联的账户/证券不兼容时阻止导入，要求显式核对。预览只读，正式导入在锁内重算，写入层同时拒绝自动改挂；原始来源判重规则保持不变。

## 0042 历史实收升级与部署顺序

三份改动按顺序合入：预计/实收及结构字段 → 三券商到账与核对 → 历史升级工具。完整版本再部署；没有新增 env，也不需要重跑财报摘要、公司分析或其他 LLM 任务。

`alembic upgrade head` 只更新结构。历史分类使用 `scripts/upgrade_dividend_receipts.py`，默认开启数据库只读事务，不会因为启动服务就自动改账。计划包含每条股息的旧值、拟修改字段、来源 ID/hash、逐账户现金变化、券商快照的升级前后差额、来源日期范围、人工核对项及账本前后指纹。

分类边界：

- 正向招商/东财红利流水与净额闭合：保留真实现金，税前/税额改为未知，旧数值留在审阅计划和行内审计备注。
- IBKR 已关联股息及同日预扣税闭合：标记凭证口径，保持来源币种列与金额。这不证明其导出基础币就是实际派发原币。
- 仅公告“接受”生成、无到账来源/批次/税款归属的记录：改为 `UNVERIFIED`，保留原值及公告关系，移出实际现金、实收、曲线和 XIRR，重新显示待核对预计。
- 来源不闭合、跨账户/用户、现金日期不一致或仍关联旧税款：整份计划阻断，不能强制跳过。
- 其他历史手工或来源不明记录：不自动猜测，列入 `review_required` 并保留旧计算；页面显示历史未核验数量，不能宣称这些也已核实。

在可丢弃的数据库恢复副本中，把当前 shell 的 `DATABASE_URL` 指向该副本，固定同一天、价格及汇率，从 `backend/` 执行（`USER_ID`、日期和目录替换为实际值）：

```bash
alembic upgrade head
python scripts/metrics_parity_report.py --user-id USER_ID --today YYYY-MM-DD \
  --out ../backups/receipt-before.json
python scripts/upgrade_dividend_receipts.py --user-id USER_ID --as-of YYYY-MM-DD \
  --out ../backups/receipt-plan.json
# 逐项检查 changes、sources、blockers、review_required、coverage 和 cash_checks 后执行
python scripts/upgrade_dividend_receipts.py --user-id USER_ID \
  --apply-reviewed-plan ../backups/receipt-plan.json --out ../backups/receipt-result.json
python scripts/metrics_parity_report.py --user-id USER_ID --today YYYY-MM-DD \
  --out ../backups/receipt-after.json
python scripts/metrics_parity_report.py --compare ../backups/receipt-before.json ../backups/receipt-after.json
# 原计划再次执行应返回 already_applied / 0 改动；新预演应 0 changes
python scripts/upgrade_dividend_receipts.py --user-id USER_ID \
  --apply-reviewed-plan ../backups/receipt-plan.json --out ../backups/receipt-repeat.json
python scripts/upgrade_dividend_receipts.py --user-id USER_ID --as-of YYYY-MM-DD \
  --out ../backups/receipt-after-plan.json
```

金额变化应能逐项解释：净收入只扣掉无到账依据的公告记录；NET_ONLY 让已知税前/税额合计及完整性提示变化，不能改变实际净现金。相关期间收益、曲线及收益率会随历史收入变化。持仓数量、真实买入成本、交易盈亏、行情输入、原始流水/hash、真实扣税和现金锚点须保持不变。工具逐项校验预期账本指纹和账户现金；失败会回滚保存点，即使调用方随后提交也不留半套升级。

生产落地沿用 [部署流程](../DEPLOYMENT.md#5-升级部署)：先完成备份及恢复验证、构建完整版本镜像，再暂停 backend/collector 和人工导入。执行结构迁移，基于此刻账本重新生成并核对计划；使用维护容器执行脚本时，把受保护的备份目录挂载到容器，并把 `--out` 指向该挂载目录。计划会核验来源、账户、交易、持仓、公司行动、税款及现金快照；任何变化均要求重新预演，不能直接复用过期副本计划。

工具不会调整现金锚点来抹平差额。`cash_checks.broker_snapshots` 明示与原券商快照的差额，移除无凭证公告造成的新差额必须继续核对，而不能称为现金已经对平。执行后重跑固定输入 metrics、核对账户现金与持仓、抽查预计/部分到账/未知税额界面，再恢复服务。数据升级后的回滚须恢复升级前数据库和旧镜像，仅降 Alembic 版本会让未核实公告重新进入旧计算。

计划和结果含私有账本，只能写 Git 忽略目录或仓库外目录，文件权限为 0600；不含新凭据配置。若结果停留在 `prepared_uncommitted`，先核对账本或重跑同一计划确认最终状态，不能凭该文件认定已提交。

### 防遗漏的证据边界

`coverage` 给出已归档来源的最早/最晚日期、最近股息日期、正向股息与扣税来源数量及未关联来源。已按现金事件入账的现金管理收入另计数量，不误列为漏记股息。最晚交易日期不等于该日期以前的股息完整；`continuous_coverage_verified` 始终为 false，只有完整对账单区间与实际现金明细核验才能确认没有遗漏。

当前 IBKR connector 的交易、持仓和汇总余额不能替代逐笔股息及扣税凭证；本次没有实现 Flex 自动取数，也不把应收冲回当作实收。#259 的原币与历史覆盖、#376 的 B 股公告派息币种仍须证据核对，不能因本组功能完成就自动关闭。
