# 前端可读性、卡片层次与深色模式提案

日期：2026-10-04。状态：**用户已批准，2026-10-04开始按A/B/C三份PR实施；完成后独立审阅，尚未部署新视觉。**

本提案承接 `FRONTEND_UI_UPGRADE_PLAN.md`，不是重新设计产品。基线为刚合入并部署的 `4a66c950e646e0dd92b351ba4eebcee20de49e98`（#445–#447）。本轮已获授权的合入、备份、部署与本提案分开记录，发布结果见总计划第50节。

用户指出七处问题：交易图表金额文字过多、图标、宋体与对比度、数字风格不一致、采集详情白底突兀、按钮不齐、展开区边距不自然。额外要求参考优秀同类开源产品、考虑深色模式，保留独立判断，避免过度设计。需要产品取舍时在回复正文提问并等待，不用提问工具。

## 1. 判断与边界

建议继续暖纸色与陶土强调的方向，调整为更清楚的墨色正文、有限的表面层级，以及用途明确的卡片。现状的问题不是“必须全部卡片化”或“必须全部宋体化”，而是平铺之后分组不够清楚、部分组件没有继承主题、同级数字的规格不一致。

- **卡片按任务分组**：资产概览、累计收益双口径、期间损益、采集器分别成为阅读单元。一个单元内相关数字共用一张卡，不给每个数套独立盒子。持仓和交易的宽表保留充分宽度，研究长文保留连续阅读。
- **宋体按内容使用**：页标题、分区标题扩大使用系统宋体；表格、操作控件和数值继续无衬线。长篇研究正文提供宋体对照供用户决定，不把全部界面改宋体。
- **对比度按信息重要性分配**：正文与重要标签用深墨色；灰字只承担辅助信息。重要的税前、预计、缺资料说明仍应易读，不能为“干净”隐藏事实。
- **数字先统一角色**：同级字号、字重、等宽数字统一，而不是再引入一套字体。保留原格式化函数、精度、币种、负号及未知值。
- **两种主题成对设计**：浅色纸面、深色炭灰；不使用整页反色、透明玻璃、重阴影或大面积渐变。

本轮不增加财务算法、数据源、模型调用或新的页面功能；不重做导航架构、不重写成熟表格/表单、不引入第三套 UI 组件库、不做通用主题编辑器。本次研究与预览不证明已达到任何设计奖项标准；实际品质需要逐页验收。

关于第1点：截图的横轴其实是日期，金额在纵轴；真正最抢眼的是图下整段金额清单。建议精简刻度，而不是把刻度全部删除，否则柱高失去量级参照。买入/卖出还可用蓝灰/陶土区分，保留文字图例；红绿继续表达盈亏，不让“卖出”自动暗示亏损。

另有一处可证实的语义错误：`views/opinions/collectorStatus.ts` 的 `collectorHealth()` 将所有 `cookie.level === 'critical'` 直接写成“Cookie 失效”，而 `cookieLabel()` 对同一记录仍显示正数剩余天数。下轮仅收窄文案判断：临近到期显示“即将到期”；有确实过期/失效依据才显示失效；依据不足保留“需检查”，不新增探活或根据倒计时推断已无法登录。对 `days_left > 0 / <= 0 / null` 做有意义的回归。

### Claude：近黑正文，衬线与无衬线分工

对 [Claude 公开登录页](https://claude.ai/login) 做只读浏览器计算样式检查：当时正文实际为 `#0B0B0B`、背景 `#FCFCFB`，正文使用 `anthropic-sans`；主要标题使用 `anthropic-serif`。中文衬线字族的回退链中也有中文无衬线字体，因此不能据此宣称 Claude 全站中文都是宋体。未登录查看私人会话，结论只覆盖该公开页面。

Anthropic 的 [品牌规范](https://github.com/anthropics/skills/blob/8a1541c4a3ffa5a20a5a91de0dcf3f0bab1d1ef4/skills/brand-guidelines/SKILL.md) 另有 `#141413`、`#FAF9F5` 等品牌色，Poppins/Lora 是该品牌文档的排版约定，不等于当前 Claude 应用使用它们。不能直接照抄品牌文档后声称还原了应用。也不下载或复用其私有品牌字体。

当前主文字与纸底的计算对比约14.9:1，本来就不低；常用辅助灰约4.74:1，三级灰约3.01:1。Claude上述公开页面约19.17:1。观感差异不仅来自数字，还来自使用深色文字的比例、字重、字体渲染和分组。三级灰只适合不承担必要信息的内容，不能拿它作正文。[WCAG 对比度依据](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：普通文字至少4.5:1，大字至少3:1；达标不等同舒适，细字渲染也会显得更淡。

### 排版与间距

- 页标题32px左右、分区标题20px、次级标题16px，系统宋体；正文14–16px、密集表格沿原密度，支持说明12–13px，但不把必要风险/税前标签缩成难读脚注。
- 数字36/28/22px对应三个明确级别，统一600字重、tabular-nums；币种与小数使用同一数值排版，不把小数淡化到看不清。
- 页面标题到首区24px；组间18–24px；组内16–24px；卡片圆角8–10px；按钮圆角6px。以上是有限规格，不建立新的布局框架。
- 卡片内部同口径并列。预览将待收额作为“含待收预计”下的构成说明，明确两种累计收益的关系；是否接受这个双列结构随本提案一起审阅。
- 原币、税额未知、部分合计、收益率与XIRR、期间待收变动细节等现有字段不能因为预览未逐一画出而删除。实际实施以现有功能清单为准。

### 字体选择

延续现有系统无衬线与系统中文衬线字体栈，先解决使用规则；不新增整包中文字体下载。Linux/Windows/macOS 的可用字体不同，不能承诺完全一样。若后续真实跨平台截图仍显示不可接受差异，再单独评估自托管子集与授权，不提前引入字体加载平台。

已确认按推荐范围：**页标题与分区标题用宋体，表格/按钮/数字与研究正文用无衬线。** 预览的正文宋体选项只供比较，本轮不加入用户字体设置。

## 5. 深色模式接入范围

当前 `App.vue` 只有静态 Naive themeOverrides 和 Element locale，没有完整外观状态。`styles.css`、`styles/naive.ts`、`styles/tokens.ts` 存在分别维护的颜色；Element保留组件和局部白色需要一并覆盖。

最小实现：

1. 三态外观：跟随系统/浅色/深色。只存浏览器偏好，不新增账户字段、后端接口或迁移；明确偏好优先于系统，默认跟随系统。初始化在首屏样式应用前完成，避免白闪；存储不可用时正常降级。
2. 沿现有 `--app-*` 定义浅深配对。Naive接入其darkTheme与对应覆盖；Element使用其深色变量入口并对齐应用语义色。不要从头实现两套控件。
3. `styles/tokens.ts` 与图表调用点使用已解析的主题色。ECharts canvas不能直接消费CSS变量，主题切换时更新配色；保留图表实例和当前范围/缩放/图例状态，不为换肤重新请求金融数据。
4. 覆盖页面、侧栏、卡片、表格、对话框、下拉/日历、tooltip、加载/空态/错误、研究Markdown、登录和404。浮层虽挂载到body，也要继承同一主题。
5. 保留当前金融含义：未知不是0，待收不是实收，普通股息不改成本；深色下也不能靠一种颜色掩盖这些差别。

不建立“可任意编辑主题色”的设置页，不新增动画、账户同步偏好或新的状态管理平台。

### 建议用于本项目的角色

| 内容 | 建议字体与处理 |
|---|---|
| 分析报告、AI复盘、财报摘要、展开后的长篇观点 | 实际加载思源宋体SC；正文英文、缩写与句内数值保持衬线语气。先检查该字体自带拉丁字形是否满足混排，确有不足才补一套拉丁正文字体，不预先堆砌字体家族。 |
| 文章标题、报告分区标题 | 沿宋体形成有限字重/字号层次。正文正常字重，避免整段加粗或中文伪斜体。 |
| 按钮、导航、表单、日期/来源、密集列表、简短状态和图说 | 思源黑体SC与Inter承担操作和辅助信息；并非“这些场景禁止宋体”，是本项目推荐的稳定分工。 |
| 金额表格、持仓数字、图表刻度 | 保持无衬线、等宽数字与对齐；等宽数字不等于所有字母采用等宽字体。币种、负号、小数、未知值及精度仍由既有格式化函数处理。 |
| 长文内的表格 | 表头与数据继续采用表格字体，段落与论述型列表采用阅读字体。不把整张表机械切成宋体，也不把段落中的每个数字切成Inter。 |

下面是本项目的试排起点，不是媒体原样规范：桌面长文18px、手机17px、行高约1.8；桌面以约36–40个汉字控制行宽，手机随可用宽度收缩。正文墨色、正常字距与字重；引用靠段落位置、适度缩进或细线区分，段落间距保持一致。短标题、作者/日期、主要结论与正文之间以有限层级建立阅读节奏，不为每段套卡片。

中文排版优先处理标点禁则、英文单词与数字单位换行、中西文字面大小与基线；避免`word-break: break-all`或手工插空格破坏内容。默认不为制造两端齐整而强行拉大字距；需要两端对齐时使用浏览器原生规则并在含股票代码、长链接、金额的实际报告上验证。`80ch`取决于当前字体的数字字宽，不能当作80个汉字；更换字体后须复查真实行长。深色也保留同一阅读字体，检查细横画和正常字重的实际显示。
