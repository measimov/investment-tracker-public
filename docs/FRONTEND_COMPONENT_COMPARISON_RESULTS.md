# 前端组件运行时对照结果

> 后续决定（2026-10-03）：用户已认可完整持仓视觉稿并授权由 6.1 sol 实施真实持仓页 Naive UI 试点；用户随后已确认左侧导航与继续按页面推广 Naive UI；最新实施状态见整体计划第 21 节。以下测量仍对应原始三库对照页，不套用于正式业务页面。

- 研究与实现：2026-10-02；验收存档：2026-10-03。
- 范围：用户批准的阶段 0；一个代表页面，Element Plus / Naive UI / Nuxt UI 三种独立实现。
- 决策状态：D4 逐页推广与 D2 可完全收起侧栏均已确认；实施范围见整体计划第 21 节。
- 代码、运行方式与原始证据：[experiments/ui-comparison](../experiments/ui-comparison/README.md)。背景：[组件研究](FRONTEND_COMPONENT_EVALUATION.md)、[整体 UI 计划](FRONTEND_UI_UPGRADE_PLAN.md)。

## 对照条件

使用相同的合成金融数据和项目原有 helpers：0.085 / 1.409 价格、真零、未知价格、未知折算汇率、大额与多币种、长名称和多行提示。各版本复用同一渲染单元和筛选/排序/校验模型。普通股息和投资成本计算没有改动。

样本按各行原币 profit 数值排序，仅检查控件和数据重排，不作为跨币种经济收益排名的业务设计。

每版包含账户与日期筛选、账户展开、固定右侧操作列、交易弹窗、中文日期、错误提示与取消重开。表格最小宽 996px、可见高 560px，名称列分配剩余空间；窄屏保持局部横向滚动。都不用虚拟化，不用简化新库表格的方式制造优势。

锁定 Vue 3.5.27、Vite 5.4.21、Element Plus 2.13.2、Naive UI 2.45.3、Nuxt UI 4.11.3。Nuxt UI 使用普通 Vue / Vite，增加 Tailwind 4.3.3；日期依赖对齐 3.12.4，未引入 Nuxt 应用框架。系统字体；没有线上账本、API、图表、外部字体。

三个候选分别构建；当前 Element Plus JS 按使用导入，CSS 与项目既有策略相同，整体前置导入。Naive 的组件样式主要随 JS 注入，不能仅比较各自 CSS 文件大小。此原型把表格与弹窗控件放在单入口，结果不代表全站迁移后的分块大小。

## 测量方法与边界

在同一 Chromium 进程中串行轮换三个候选，以 50/200 行和冷上下文/缓存重访分为 12 组；每组排除一次预热，取五次有效样本的中位数，并保留范围和原始观测。没有 CPU/网络限速。冷上下文并非系统或浏览器进程冷启动，缓存命中以 Resource Timing 为准。

ready 是 Vue 挂载后等待两帧的里程碑。筛选/排序/弹窗通过共同模型驱动，展开使用原生触发器，滚动通过实际表格容器的 scrollTop；均计入两帧等待。**这些数据不是 INP**：弹窗没有等待全部 CSS 过渡结束，滚动跳转不等于持续滚动的 FPS 或流畅度，几毫秒差异可能落在帧调度与环境波动内。独立 UI 检查另验真实控件行为。

## 实测摘要

建议 Naive UI；它在本页 200 行样本的渲染与更新更快，压缩体积仅比现有方案增加约 2.2%。默认 50 行时三版主要操作普遍接近，不能据此宣称全部页面或所有交互都有同等提速。

构建体积单位为十进制 KB，包含本页使用的 Vue 与控件，不含 HTML；JS/CSS 分别 gzip 后相加。

| 方案 | JS gzip | CSS gzip | 合计 gzip |
|---|---:|---:|---:|
| Element Plus | 166.7 | 48.4 | 215.1 |
| Naive UI | 218.8 | 1.2 | 220.0 |
| Nuxt UI | 211.2 | 26.3 | 237.5 |

ready 耗时单位 ms，单元格为中位数（五次范围）：

| 方案 | 50 行冷上下文 | 50 行缓存重访 | 200 行冷上下文 | 200 行缓存重访 |
|---|---:|---:|---:|---:|
| Element Plus | 168.2（165.8–171.9） | 86.4（84.8–90.2） | 282.1（281.1–290.6） | 197.9（196.5–200.9） |
| Naive UI | 153.2（151.1–158.6） | 57.9（57.4–58.2） | 233.4（229.5–237.5） | 131.8（129.8–138.2） |
| Nuxt UI | 151.5（149.4–152.1） | 86.1（85.3–88.2） | 288.1（280.7–295.9） | 213.3（212.3–228.0） |

200 行缓存重访后的操作中位数（ms，包含两帧等待；不是 INP）：

| 方案 | 账户筛选 | 重置 | 降序排序 | 展开 | 打开弹窗 | DOM 元素 |
|---|---:|---:|---:|---:|---:|---:|
| Element Plus | 70.5 | 107.5 | 110.5 | 48.6 | 32.7 | 7744 |
| Naive UI | 29.3 | 67.0 | 50.7 | 26.0 | 34.6 | 6022 |
| Nuxt UI | 64.5 | 161.9 | 119.5 | 81.2 | 32.1 | 5113 |

Nuxt UI 的 DOM 最少，但此页 200 行重置/排序未比 Element Plus 更快，说明 DOM 数不能单独当性能结论。Naive 的表格收益没有以删字段或虚拟化少渲染来换取；所有试验均断言实际渲染了要求的 50/200 个价格单元。

测量环境：Linux x64、AMD Ryzen 7 9700X 8-Core Processor、Chromium 148.0.7778.96、Node v22.23.0，1440×900。最终 72/72 次成功，其中 12 次预热排除、60 次有效；交互检查 36/36 通过，三版 typecheck/build 均通过。手机检查为 393×852。

长任务归因曾漏记跨越操作计时起点的任务；已改为区间相交并重跑完整 72 次。本文只采用最终结果；首轮文件保留用于溯源，不把初轮操作长任务为零解释为没有卡顿。

## 交互与适配发现

共同验收覆盖：金额与空值、搜索和重置、50/200 行切换、账户与包含起止日的日期过滤、双向排序与未知值排末、展开和逐行编辑、空值/零价校验及 0.085 保存、取消重开、遮罩保留草稿、Tab 焦点约束、Escape 与焦点返回、393px 表格滚动和编辑可达。

| 方案 | 此页实际需要的补齐 | 迁移含义 |
|---|---|---|
| Element Plus | 可聚焦排序按钮与排序语义；数字输入步长与四位小数一致；日期测试标识放在容器 | 主题和页面布局可以直接改善；现有控件使用也需逐项验收 |
| Naive UI | 中文 locale / themeOverrides；日期实际 input 的标签透传、Select 焦点标签、排序按钮和 `aria-sort` | 后台功能足够，但不能从“完整组件”推定自带完整键盘语义；补丁要维护 |
| Nuxt UI | 纯日期对象与 YYYY-MM-DD 转换、日期依赖去重、主题与层级配置、表格列定义/展开/固定、保留下拉原有键盘文本注册 | 组件组合和视觉配置灵活；需要新构建/样式基础设施及更多边界适配 |

对照过程保留了真实问题及修正记录：

- Element Plus 数字控件即使设置 `precision=4`，默认 `step=1` 仍会使 0.085 的原生 form 提交失败；本原型改为 `step=0.0001`。这不等于已证明生产页有同一问题，生产的按钮提交路径不同。
- Nuxt UI 日期库两个版本造成私有 DateValue 类型不兼容，锁定同版去重后通过，未靠强转掩盖。
- Nuxt UI 浮层与固定表头需要显式层级；去图标时须保留下拉组件原本的键盘文本注册。
- 初轮部分失败来自测试适配：Element 错误提示需要等待可见、数量末尾零应按数值比较、Reka 日期分段直接输入替换而非先删一个字符。原始失败不拿来当组件缺陷统计。

这些验证不是全站无障碍认证；没有完成屏幕阅读器、中文输入法、所有浏览器或所有复杂表格组合审计。原型未复制文件导入、异步证券搜索、图表、生产请求/分页等完整业务。

## 建议与待确认决策

**用户已确认 Naive UI 真实持仓页试点，并在交付后确认继续逐页推广。Nuxt UI 不进入本轮迁移。**

理由是此次代表页上较大表格的渲染/更新有实际收益、体积接近现有方案，并有完整中文表单及类型化主题配置，无需引入 Tailwind 或改变现有 Vue / Vite 架构。必要样本交互已验收；键盘标签与排序仍需少量适配，不能称为全方位优于旧库。三版都能实现同一暖色视觉，单靠外观不足以决定换库。

若只是改颜色和排版，保留 Element Plus 也足够；采用 Naive 的理由应是把实测表格收益和主题维护一起纳入本轮升级。全站迁移依然要替换大量组件及测试，本次没有证明其余全部页面都可无成本迁移，也不承诺线上同等百分比提速。

确认后的最小步骤：

1. D4 已记为「继续按页面推广 Naive UI」；D2 可完全收起侧栏也已确认。
2. 先做最小主题与全局提示/确认，随后迁移一个完整持仓页面作为首个业务验收点，复用现有 composable、金额 helpers、API 和业务状态。
3. 该页回归通过后，将真实页面效果、包体和回归成本交给用户决定是否推广；确认后按原计划迁移交易及其余页面。新旧组件只在页面边界临时隔离，不建跨库适配框架，不在同一表单混两套交互。
4. 若确认全站迁移，完成后删除 Element Plus 与旧覆盖样式，重新测全站依赖和主路径；若真实页收益不足则撤回试点。实验目录归档，不永久维护重叠组件库。

用户本轮只授权对照，因此这里没有开始业务迁移或部署。

## 后续边界

如保留 Element Plus，按原 UI 计划做暖色主题、布局与表格/表单体验改造；不维持三套库。若决定换库，先确认一套目标，再按页面分组迁移，金融 helpers、取数与会计口径保持复用。

现有项目有 60 个 Vue 文件引用 Element 组件、37 处表格、20 处对话框、15 个 E2E spec 直接耦合 `.el-*`。新库没有自动消除这部分替换与验收成本。此次实验文件独立，可在选型完成后归档；不把测试抽象变成正式产品的跨库兼容层。
