# 财报分析的事实输入与本轮修复

本轮处理 #385、#388、#386 和 #289 中尚未封住的共同入口。数字先在代码里去重、统一口径、核对，再交给模型写报告。没有增加新的分析系统、数据库表或账本迁移。

## 输入规则与修改点

| 问题 | 修改 | 缺信息时的处理 |
| --- | --- | --- |
| 同一次实施分红挂在两个报告期下 | `analysis_signals.implemented_dividends` 在报告期内修订去重后，再按明确的除息日、实施公告日、每股税前金额、送股比例合并；归属较晚报告期并保存合并来源。汇总与报告例证共用 | 日期/金额缺失、有修订冲突，不跨期猜测合并 |
| 自由现金流的数值和公式不一致 | 最新年报/中报提供预计算 FCF；分析输入只送主口径及公式，原始表和另一口径留在档案中 | CFO/资本开支不齐时，仅能使用明确标注来源的现有 FCF；无可用值就留空 |
| 港股 PDF 与 Yahoo 的同科目冲突 | 送模型前，Yahoo 同期行仅保留 PDF 缺失的科目；双方已知同币种才补缺 | 币种不同或未知，不拼接金额 |
| 以缺失风险摘要推断年报没风险章节 | 按报告期引用已提供的风险内容；旧 AI 摘要中的无依据章节断言在输入投影中改为节选覆盖未核验，保留相邻的具体风险；不改源缓存 | 港股风险等级下限仍为 medium |
| 摘要数字核对把年份/百分比/解释文字当成金额 | QA v3 只解析带单位的明确金额，识别亏损符号与繁体单位；调整利润、分部收入不替代合并科目 | 无法确认金额/币种/口径，标为未核对，不冒充通过 |
| 错误摘要继续进入商业画像 | 确有核心数字矛盾的摘要整期从 LLM 输入隔离，保留原缓存与核对说明；主分析和商业画像共用门禁 | 不把“隔离”写成“公司没披露”，不擅自用报表数字改写摘要正文 |
| 刷新失败后沿用旧画像污染新分析 | 主分析读取画像必须匹配 prompt v4 和当前输入指纹 | 不匹配就不引用，并明确列出缺口 |
| 直接组装分析输入时遗漏摘要缺口 | 未传入缺口时，自动调用已有的只读缓存预览 | 不联网补报告；清单未知与确实没有摘要分开描述 |

QA 只对摘要中可比的合并营业收入、归母净利做核对，不覆盖全部分部数字和业务叙述。通过两个科目不代表整份摘要或最终报告已证明无误。原始报表抽取质量仍由现有报表校验负责；#379 的 PDF 断字解析、#337 的整体快照架构以及 #389 的小数展示没有混入本轮。

## 固定真实数据核对

使用 `45cb136` 部署前已生成的备份恢复到隔离数据库，固定数据日 2026-10-02；组装过程使用只读、可重复读事务。共 66 个标的、422 份可加载摘要。私有输入与完整对比保存在 Git 忽略的 `backups/factual-integrity-20261002/`，不提交账户数据或凭据。

现有年度分红数值变化只有 300750 的 2024 年：

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 每股分红（元） | 7.013 | 5.783 |
| 股息总额估算（亿元） | 307.32 | 253.42 |
| 股息支付率 | 60.6% | 49.9% |
| 股息/自由现金流 | 46.7% | 38.5% |

股息总额仍是每股分红乘隐含股数的估算，不是公司披露的精确年度支付额。66 个标的的格雷厄姆判定没有变化。

最新中报按 CFO 减资本开支绝对值计算：300750 为 351.44 亿元、601058 为 -15.65 亿元、605016 为 +1.56 亿元、000807 为 81.71 亿元。回归用例还覆盖 FCF 两个定义正负相反的情形。

旧核对的 26 份摘要告警在修正金额/符号/科目识别后消失；实际可比科目由 656 个减为 623 个，其余明确保留未核对状态。这不是宣称 422 份摘要全部核对通过，也没有放宽原有 2%/舍入容差。

已缓存的 45 个商业画像需要按 v4/新输入刷新。已有报告不会因部署被自动重写，修复输入只影响新生成报告。

## 模型对照与限制

经用户单独授权，对 300750、601058、605016、00148、00700、01995 分别做一次改前/改后采样，共 12 次、564,461 tokens，均使用 DeepSeek `deepseek-flash` 且解析成功。改后 300750 引用 5.783 元，601058 的 2026H1 FCF 从改前误引的 -9.16 亿元改为 -15.65 亿元；605016 正确引用 +1.56 亿元；00700 按 PDF 口径引用资本开支 874.82 亿元和年度 FCF 2,155.70 亿元。

这轮还发现：00700 改后报告仍照抄旧摘要的“未设风险章节”。因此继续增加上述风险摘要投影修正，并用同一份 66 标的输入及回归测试核验；没有超出授权追加模型调用。最终投影修正尚未另做模型采样。改后对照未调用模型刷新 45 个过期画像，主分析按门禁排除了它们；部署后应先完成画像刷新再验收报告内容。

## 合入后的落地顺序

1. 常规备份应用表、部署合入版本、检查健康及 schema。此轮没有 Alembic 迁移，也不重建持仓/现金或股息记录。
2. 先预览画像更新：`python scripts/refresh_business_profiles.py`；再用 `--apply` 更新过期的存量画像。脚本以版本/输入指纹续跑，失败退出非零且不让旧画像回流主分析。每个过期标的通常一次 LLM 调用。
3. 不需要为 QA v3 重下载财报、清空摘要或全量付费重摘要。QA 在读取时按当前报表现算；确有矛盾的具体摘要另行核对来源后处理。
4. 重跑 300750、601058、605016、000807 以及港股中仍显示旧风险说法/双源数值的分析。需要统一口径时再重跑全部现有分析；保留旧报告历史。
5. 检查新报告的分红、FCF 数字/公式/期间、风险来源与缺口，确认部署行为后关闭 #385、#388、#386。#289 是总清单，未逐项核完前保留。

自动化测试验证输入口径和隔离行为；少量模型对照用于观察真实生成效果，不能保证此后的每次模型采样都无事实错误。
