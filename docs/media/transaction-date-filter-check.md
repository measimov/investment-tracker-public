# 交易日期筛选验收

本轮依据 [已确认计划第 22 节（#415）](https://github.com/measimov/investment-tracker/blob/codex/ui-design-records/docs/FRONTEND_UI_UPGRADE_PLAN.md)。分支 `codex/transaction-date-filter` 依赖仪表盘 [#418](https://github.com/measimov/investment-tracker/pull/418)，日期功能与后续交易视觉迁移分开审阅。

列表与计数接受 `start_date` / `end_date`，均包含首尾日期。单侧参数也可用于 API；日期控件提供完整范围。反向范围返回中文 422，无效日期按现有请求校验返回 422。无新字段、索引、迁移、财务算法或取数设施。

页面复用既有 Element Plus 日期控件，值为 `YYYY-MM-DD`；列表与 count 共用同一组参数，沿用 `usePagedList` 回首页、旧请求守卫和 `paramsKey` 缓存。手机日期算一个筛选，清空与重置沿用原查询。导出仍沿用既有全量导出接口，此日期筛选只作用页面列表和计数。表单、导入、只读来源、转仓配对删除与账户标签未改。

## 正式截图与实际缺陷

同一虚构 demo 账本，未重灌、修改真实账户或外呼研究任务。桌面截图已完成查询，范围 2026-01-01 至 2026-12-31 显示 4 条，与 API 一致；手机图展示日历打开态。

- [1440×852 @1x：日期范围与完成后的列表](transaction-date-filter.png)
- [393×852 @2x：双月日历在窄屏上下排列](mobile-transaction-date-filter.png)

自查发现默认双月日历宽 646px，在 320px 视口越界。本页专用 `popper-class` 在窄屏将既有两个面板上下排列，保留库的月份导航、日期选择、键盘与滚动。仅改宽度仍会纵向越界，因此通过公开 `popper-options` 的 `preventOverflow` 参数启用另一轴约束并解除锚点牵连；未新增定位算法。浮层高度限制为视口减 32px，短屏可滚动。
