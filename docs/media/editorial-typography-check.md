# 长文与字体交付验收（2026-10-04）

范围见[提案第11节](../FRONTEND_UI_REFINEMENT_PROPOSAL.md)及[总计划第57节](../FRONTEND_UI_UPGRADE_PLAN.md)。基于 main `cd93ee2`，先检索实际入口和加载机制，再由 6.1 sol 分别实施、主代理独立检查。未选择新配色或品牌图标。

## 实际交付

- 正文使用 **Noto Serif SC Variable**（思源／Noto 同源家族的 Google Fonts SC 网络版本），其自带拉丁字形承接英文与句内数字。UI 使用 Inter Variable + Noto Sans SC Variable。
- 报告、追问答复、标的分析、财报叙述、展开的观点与引用沿原组件呈现。桌面 18px、手机 17px、行高 1.8、最大 38em；不增加阅读器或修改 Markdown 内容。
- 表格保持无衬线、原字号与金额精度，代码保持等宽；日期、来源、字段标签、短预览与辅助说明保持 UI 字体。Markdown 的语义强调使用真实 600 字重，避免中文合成斜体。
- 三套 Fontsource 变量包锁定 5.3.0，沿用现成 Unicode 分片与 `font-display: swap`；由同源提供，原始 OFL 许可随部署发布。
- 验收复现图表字体下载后不重绘、字宽仍缓存回退字体。仅在四个既有图表入口延后首次 option；正常就绪才绘图，失败或等待超过 8 秒的实例固定系统字体，避免迟到字体改变缓存。保留实例、数据、占位及原有更新方式。

## 实测边界

| 项目 | 结果与限制 |
|---|---|
| 真实字体 | Chromium 渲染字体检查确认中文、正文英文和句内数字由自托管 Noto Serif 绘制，UI 与表格保持无衬线；不是仅检查 CSS 名称。变量字体的内部名称含 ExtraLight／Thin，不代表正文 CSS 字重改成极细。 |
| 阅读页面 | Chromium 320／393／1440px × 浅深色；Linux WebKit 393／1440px × 浅深色，检查报告、AI 答复、分析、财报、观点全文与展开摘要。不是 Windows／macOS 真机测试。 |
| 内容与排版 | 使用现有明确虚构 fixture，额外加入中英混排、负金额、0.0851、未知值、长段及代码。表格保留横向滚动，正文不撑宽页面，复制原文不变。 |
| 字体总资源 | 部署含 205 个 WOFF2 文件，共 10,751,304 B；另 4 个小分片按既有 Vite 规则内联 CSS，共 11,708 B 字体二进制。不是每个页面全部下载。 |
| 报告冷加载 | 本次完整虚构报告请求 23 个 WOFF2，正文载荷共 1,503,616 B；不同文字会请求不同分片，不能推广为全站固定大小。 |
| 冷／暖缓存 | 无路由拦截的登录页：冷访问字体正文 536,820 B；同一上下文再次访问正文 0 B（预览服务有少量重验证响应头）。生产 Nginx 原有哈希字体一年缓存与同源 CSP 保持。 |
| 加载失败／延迟 | 320／1440px 阻断字体文件后仍可读、可用键盘切换报告，系统宋体回退；延迟释放后文字内容一致。未把首屏无字体闪换说成零布局变化。 |

WebKit 原生 Markdown 表格不能自动聚焦、报告页有 `ResizeObserver loop completed with undelivered notifications` 提示。已用相同 fixture 在旧预览（16px 系统字体）与本轮页面对照复现，两者一致；没有将其记为零错误通过。WebKit 用水平滚动验证内容可达，Chromium 另验证键盘滚动；本轮没有扩改 Markdown 渲染器。

实际量测摘要见 [验收数据](editorial-typography-evidence.json)。

24点虚构曲线的图例／缩放操作会改变实际图形；主题切换后的整图像素不全等，在准确main `cd93ee2`基线亦复现。本轮未改变原交互更新机制，也未用像素相等声称已证明全部缩放状态。
