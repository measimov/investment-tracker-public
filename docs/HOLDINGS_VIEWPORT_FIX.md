# 持仓临界宽度显隐修复

2026-10-04，基线 `5023f896`。

持仓等页面已通过 `useMediaQuery` 和 `v-if` 选择表格或卡片，共享 CSS 又按断点隐藏它们。WebKit 出现滚动条时，两次判断可能暂时不同，形成“已渲染的表格被隐藏 → 布局变化 → 再次判断”的循环。

本机 Linux WebKit 原生复现：账户与标签搜索后按 Esc，切到按账户；641、647、648px 下桌面容器变为 `display:none`，顶部仍有一只持仓，转仓入口消失，并出现 ResizeObserver 循环错误。此前 macOS 的独立报告见 [原审查记录](https://github.com/measimov/investment-tracker/pull/442#issuecomment-5972647035)。

修复只删除共享 CSS 的二次隐藏，卡片容器保留 grid 和间距；断点、页面渲染分支、数据和操作不变。所有使用这两种容器的现有页面均由 `v-if` / `v-else` 控制挂载。

验证：

- 相同原生 WebKit 在393、633、640、641、647、648、1440px七宽下明细及转仓入口均可见，页面错误消失；Chromium同七宽通过。
- Chromium CI的两项回归显式模拟CSS与媒体查询两种分歧，检查明细可见、转仓弹窗可打开及取消。两项在原CSS下均失败，修复后通过；模拟不冒称WebKit原生测试。
- 不代表iOS或macOS真机完整验收；本机原生验证使用Linux引擎和虚构API数据。

无后端、环境或数据迁移，无需重跑分析。后续完整CI及集成回归证据记录在PR正文。
